## 1. Overview

The UI ships with six languages.

| Language | Code | Catalogue |
| --- | --- | --- |
| English (default) | `en` | `locale/en/LC_MESSAGES/django.po` |
| 中文 | `zh-hans` | `locale/zh_Hans/LC_MESSAGES/django.po` |
| Français | `fr` | `locale/fr/LC_MESSAGES/django.po` |
| Deutsch | `de` | `locale/de/LC_MESSAGES/django.po` |
| Español | `es` | `locale/es/LC_MESSAGES/django.po` |
| 日本語 | `ja` | `locale/ja/LC_MESSAGES/django.po` |

| Item | Value |
| --- | --- |
| `LANGUAGE_CODE` | `en` (override with `DJANGO_LANGUAGE_CODE`) |
| `LANGUAGES` | `en`, `zh-hans`, `fr`, `de`, `es`, `ja` |
| `LOCALE_PATHS` | `locale/` at the project root |
| Switch endpoint | `/i18n/setlang/` (`django.views.i18n.set_language`) |
| Storage | `django_language` cookie (browser session) |
| Switcher position | top right, next to the account chip (fixed top right on the login page) |

Each language is listed **in its own language** (`English`, `中文`, `Français`,
`Deutsch`, `Español`, `日本語`) - see
[Names in the switcher](#names-in-the-switcher).

**The source strings are Chinese.** Templates use `{% translate "…" %}` and
Python code uses `gettext()` / `gettext_lazy()` around Chinese literals, so the
`msgid` of every entry is Chinese and the `msgstr` in `locale/en` holds the
English text.

Because Django falls back to the default language's catalog when a translation
is missing, `locale/zh_Hans` is an **identity catalog** (`msgstr == msgid`).
Without it, switching to Chinese would still render English.

## 2. How the language is chosen

`apps.core.middleware.DefaultLanguageLocaleMiddleware` (a `LocaleMiddleware`
subclass registered right after `SessionMiddleware`) resolves the language from,
in order:

1. the language prefix of the URL (not used by this project),
2. the `django_language` cookie — set by the switcher form,
3. `LANGUAGE_CODE` (`en` by default).

The browser `Accept-Language` header is **ignored**, so English stays the
default even on a browser configured for Chinese. Set
`DJANGO_LANGUAGE_FROM_BROWSER=True` (`settings.LANGUAGE_FROM_BROWSER`) to
restore Django's standard header-based detection.

The switcher is a small form in `templates/includes/language_switcher.html`,
included by `templates/base.html` at the top right of the main content
(logged in) and as a fixed element on the login page (anonymous). It posts
`language` and `next` to `/i18n/setlang/`.

Because the cookie is a browser-session cookie, a fresh browser session always
starts in English again; the choice only lives until the browser is closed or
until the visitor picks another language.

### Names in the switcher

`settings.LANGUAGES` stores the **native** name of every language and the names
are deliberately *not* wrapped in `gettext_lazy`. `{% get_available_languages %}`
would translate them a second time - Django's own catalogues turn `English`
into `英语` or `Anglais` - so the switcher iterates
`AVAILABLE_LANGUAGES_NATIVE`, provided by
`apps.core.context_processors.languages`. Use that variable (or
`settings.LANGUAGES` directly) whenever you render a language list.

To switch programmatically:

```python
from django.utils import translation
translation.activate('zh-hans')
```

## 3. Adding or updating strings

1. Wrap the new text:

   ```django
   {% load i18n %}
   <h1>{% translate "预测结果" %}</h1>
   ```

   ```python
   from django.utils.translation import gettext as _     # or gettext_lazy in models

   messages.success(request, _('上传成功'))
   ```

2. Re-extract the catalogs (both languages at once):

   ```bash
   python manage.py makemessages -l en -l zh_Hans --ignore=".venv/*"
   ```

3. Fill in the English `msgstr` in `locale/en/LC_MESSAGES/django.po`, and copy
   the new `msgid` into the `msgstr` of `locale/zh_Hans/LC_MESSAGES/django.po`
   (the catalog is an identity mapping — the helper below does it for you):

   ```bash
   python scripts/sync_zh_catalog.py
   ```

4. Compile and verify:

   ```bash
   python manage.py compilemessages
   python manage.py runserver   # switch language and check the new string
   ```

## 4. Adding a new language

1. Add the language to `LANGUAGES` in `config/settings.py` with its **native**
   name and without `gettext_lazy`, e.g. `('ko', '한국어')`.
2. `python manage.py makemessages -l ko --ignore=".venv/*"`
3. Translate `locale/ko/LC_MESSAGES/django.po` (308 entries).
4. `python manage.py compilemessages`
5. The language appears automatically in the switcher dropdown.

## 5. Localised dates

`strftime()` always produces language neutral output such as `2025-01`, so a
Chinese page would still show a numeric, English-looking date. Templates
therefore use the filters of `apps/core/templatetags/i18n_dates.py`:

```django
{% load i18n_dates %}
{{ item.date|localize_date }}    {# 2025年1月15日 · Jan. 15, 2025 · 15 janvier 2025 #}
{{ month|localize_month }}       {# 2025年1月 · January 2025 · janvier 2025 #}
```

`localize_date` uses the locale's `DATE_FORMAT`, `localize_month` the locale's
month name; both rely on Django's own catalogues, so month names are already
translated. The year/month pattern itself is translatable through the msgid
`#year#年#month_num#月` (`#month_name# #year#` in English, `#year#年#month_num#月`
in Japanese); `#…#` tokens are used because `msgfmt` would otherwise treat the
entry as a brace format.

Keep ISO values (`|date:"Y-m-d"`) wherever the value is submitted back to the
server, e.g. inside `<input type="date">` and in `data-*` attributes used by JS.

## 6. Two pitfalls

**Percent signs.** `django.utils.translation.template.templatize()` escapes `%`
as `%%` while extracting strings from templates. The catalog key therefore
contains `%%` while the runtime string contains `%`, and the entry never
matches. Keep literal `%` characters *outside* the tag:

```django
{# wrong: the catalog key becomes "变化%%" #}
{% translate "变化%" %}

{# right #}
{% translate "变化" %}%
```

The same applies inside attributes and inline JavaScript.

**JavaScript.** Text inside `<script>` blocks is translated server side, inside
the string literal:

```javascript
alert('{% translate "请选择销售区域" %}');
```

Only string literals are safe to translate — never wrap statements or comments.

## 7. Checklist for contributors

* [ ] New UI text wrapped with `{% translate %}` / `gettext()`
* [ ] `makemessages` run for **every** language (`en zh_Hans fr de es ja`)
* [ ] English `msgstr` filled in, Chinese catalog re-synced, other catalogs updated
* [ ] `python manage.py compilemessages` executed
* [ ] Page checked in English and Chinese; dates use `|localize_date` / `|localize_month`
* [ ] No literal `%` inside a `{% translate %}` tag
